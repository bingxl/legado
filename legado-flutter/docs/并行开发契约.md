# 并行开发契约（M1–M5 阶段）

> 多个 agent 同时改 `packages/legado_core` 时，**只有目录所有权不重叠才不会互相覆盖**。
> 本文件是硬约束：动手前先确认自己的目录，越界的改动一律回退。

## 一、目录所有权

| 角色 | 独占目录 | 可读不可写 |
| --- | --- | --- |
| **store**（M1 数据层） | `lib/src/domain/`、`lib/src/store/`、`test/store/` | 其余全部 |
| **rules**（M2 规则引擎） | `lib/src/rules/`、`lib/src/util/`、`test/rules/` | `lib/src/domain/`（只读实体字段） |
| **js**（M2 JS 解释器） | `lib/src/js/`、`test/js/` | 其余全部 |
| **net**（网络层） | `lib/src/net/`、`test/net/` | `lib/src/util/` |

**所有人都不许改**：

- `pubspec.yaml`（根、core、cli、app）—— 依赖由主控统一加，冲突面最大
- `lib/legado_core.dart`、`lib/src/core.dart`、`lib/src/kernel/*`、`lib/src/modules/*`
- `lib/src/kernel/errors.dart` 的错误码（UI 按字符串分支，改一个就崩一片）
- `app/`（Flutter UI）——本阶段不碰 UI
- `analysis_options.yaml`

需要新增公开导出或方法时，**在自己的 README 或返回值里说明**，由主控统一接进门面。

## 二、依赖已经加好

`packages/legado_core/pubspec.yaml` 现有：`sqlite3 3.5.2`（native assets，Windows/Android 自动编译，无需自带 dll）、
`html 0.15.7`、`csslib 1.0.2`、`xml 6.6.1`、`archive 4.7.1`、`gbk_codec 0.4.0`、`http 1.6.0`、
`collection`、`crypto`、`logging`、`path`。

**不要 `dart pub add`**：workspace 只有一个 lockfile，并发 add 必然互相覆盖。

## 三、绝对红线

1. `packages/legado_core` 里 **不许出现 `package:flutter` / `dart:ui`**，
   `test/no_flutter_import_test.dart` 会直接失败。所有能力必须纯 Dart。
2. 不许新建 `lib/src/` 下的顶层目录（如 `lib/src/service/`），那是下一阶段的事。
3. 不许 `git commit` / `git checkout` / `git stash`。改动留在工作区，由主控统一提交。
4. 不许跑 `flutter build` / `flutter test`（会和主控的构建验证抢 Gradle 锁）。
   只跑 `dart test` 和 `dart analyze`，且**只跑自己目录下的测试**。

## 四、运行环境

```powershell
$env:PUB_HOSTED_URL = "https://pub.flutter-io.cn"   # 内网代理连不上 pub.dev
cd C:\Users\bingx\work\code\legado\legado-flutter
dart test packages/legado_core/test/store      # 换成自己的测试目录
dart analyze packages/legado_core
```

首次跑 `dart test` 会触发 `Running build hooks...`（sqlite3 native assets 编译），**约 1–2 分钟**，
属正常现象，不是卡死。第二次有缓存。

## 五、真源（唯一权威）

原版 Kotlin 是功能与语义的唯一真源，**不要凭印象写，去读**：

| 内容 | 路径 |
| --- | --- |
| 实体字段 / 表名 / 索引 | `app/src/main/java/io/legado/app/data/entities/*.kt` |
| 建表与迁移 | `app/src/main/java/io/legado/app/data/DatabaseMigrations.kt` |
| DAO 的 SQL | `app/src/main/java/io/legado/app/data/dao/*.kt` |
| 规则解析 | `app/src/main/java/io/legado/app/model/analyzeRule/*.kt` |
| 常量枚举 | `app/src/main/java/io/legado/app/constant/*.kt` |
| 网络与 Cookie | `app/src/main/java/io/legado/app/help/http/*.kt` |

规则引擎的 Go 版实现（已删除但可从 git 取回）语义更接近 Dart 要写的目标：
`git show c8a3813:core/...` 或 `git show c8a3813:legado-go/pkg/rule/*.go`。

## 六、完成标准

每个 agent 交付时必须做到：

1. 自己目录下 `dart test` 全绿，且**新增用例数 > 新增文件数**（纯 CRUD 搬运不算工作量）。
2. `dart analyze packages/legado_core` 零 issue（`info` 也算）。
3. 在 `docs/进度-<角色>.md` 写：做了什么、没做什么、留给谁、踩了什么坑。

第 3 条不是形式主义：下一个 agent 接手时，这 5 行决定他能不能 10 分钟内上手。
