# 书源字段表（BookSource JSON 契约）

> 真源：`app/src/main/java/io/legado/app/data/entities/BookSource.kt` + `BaseSource.kt`
> + `data/entities/rule/*.kt`。
>
> **兼容性要求（规划文档 §5）**：书源 JSON 100% 兼容，用户从原版 Legado 导出的
> `bookSource.json` 必须能原样导入并工作。所以字段名、类型、默认值都不能「顺手改好」。
>
> 关键事实：**整个实体没有任何 `@SerializedName` / `@Expose`**，GSON 按字段名直出，
> 因此 **JSON key == Kotlin 属性名 == SQLite 列名**，三者一字不差。

## 一、顶层字段（30 个）

## 附录 1：`bookSourceType` —— 枚举，**不是位域**

真源 `constant/BookSourceType.kt`（`@IntDef`，只允许这 4 个值）：

| 值 | 名称 | 含义 | 对应 `book.type` |
| ---: | --- | --- | --- |
| `0` | `default` | 文本（默认，绝大多数源） | `8`（text） |
| `1` | `audio` | 音频书（章节「正文」是音频地址规则串） | `32`（audio） |
| `2` | `image` | 图片/漫画书 | `64`（image） |
| `3` | `file` | 只提供下载的网站（如知轩藏书） | `128`（webFile） |

**没有组合值**：类型是单选。要组合的是 `book.type`（附录 2），别把两个概念混在一起。

## 附录 2：`book.type` 位域（以 Kotlin 为准）

真源 `constant/BookType.kt`。**每一位一种类型**，可叠加；`>=8` 是为了与老版本类型区分。

| 位 | 十进制 | 常量 | 含义 |
| --- | ---: | --- | --- |
| `0b1000` | **8** | `text` | 文本 |
| `0b10000` | **16** | `updateError` | 更新失败（状态位，不表示内容类型） |
| `0b100000` | **32** | `audio` | 音频 |
| `0b1000000` | **64** | `image` | 图片/漫画 |
| `0b10000000` | **128** | `webFile` | 只提供下载的网站 |
| `0b100000000` | **256** | `local` | 本地书 |
| `0b1000000000` | **512** | `archive` | 来自压缩包（解压导入） |
| `0b100_0000_0000` | **1024** | `notShelf` | 未正式入架的临时书（`Previewing`） |

组合常量：

| 常量 | 值 | 组合 |
| --- | ---: | --- |
| `allBookType` | **232** | `text｜image｜audio｜webFile` = 8+64+32+128 |
| `allBookTypeLocal` | **488** | 上一行 + `local` = 232+256 |

其他常量：`localTag = "loc_book"`（本地书的 `origin`）、`webDavTag = "webDav::"`（WebDAV 书的 `bookUrl` 前缀）。

> ⚠️ **Go 版只实现了 `text=8` / `audio=32` / `image=64` 三个**（`core/domain/book.go` 的
> `BookTypeText/Audio/Image`），没有 `updateError` / `webFile` / `local` / `archive` / `notShelf`。
> Dart 侧要补齐 8 个常量：书源 JS 会直接读 `book.type`（`=== 64` 判断漫画、`& 128` 判断下载站），
> 少一位就静默失效，而且这种失败不报错、只是「看着不对劲」。
>
> 判断类型时**用位与而不是相等**：`(type & 32) != 0` 而不是 `type == 32`（书可能是 8|32）。

## 附录 3：内嵌 JSON 字符串字段的真实结构

这四个字段在 JSON 里是 **String**，但内容是 JSON（甚至 JS）。解析一律要**宽松**
（GSON lenient 等价能力）：裸键、单引号、尾随逗号、注释都要能吃。

### 3.1 `header` — 请求头对象

```json
{"User-Agent":"Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"}
```

真实样例（`sources/t66y_book_source.json`）：

```json
"header": "{\"User-Agent\":\"Mozilla/5.0 (Windows NT 10.0; Win64; x64) ... Chrome/120.0.0.0 Safari/537.36\"}"
```

三种形态：

| 形态 | 处理 |
| --- | --- |
| 普通 JSON 对象 | `Map<String,String>` 直接用；**数字值要转字符串** |
| `@js:` / `<js>` 前缀 | 先执行 JS，把返回值当 JSON 解析 |
| 非法 JSON | 宽松解析；仍失败则记日志并**忽略**（不要因此让整个请求失败） |

合并顺序（`BaseSource.getHeaderMap`）：书源 `header` → 若无 `User-Agent` 补全局 UA →
若 `hasLoginHeader=true` 再叠登录头（登录头优先）。

### 3.2 `loginUi` — 登录表单（`RowUi[]`）

```json
[
  {"name":"账号","type":"text"},
  {"name":"密码","type":"password"},
  {"name":"登录","type":"button","action":"@js:login()","style":{"layout_flexGrow":1}}
]
```

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `name` | String | `""` | **表单键名**。登录脚本里用 `result['账号']` 取值，也是 `SourceLogin.Login(form)` 的 key |
| `type` | String | `"text"` | `text` / `password` / `button` 三选一；其他值**跳过该行** |
| `action` | String? | `null` | 仅 `button` 用：`@js:` 脚本片段，或 URL |
| `style` | Object? | `null` | Flexbox 布局：`{layout_flexGrow, layout_flexShrink, layout_alignSelf, layout_flexBasisPercent, layout_wrapBefore}` |

两种存法都要认（老版本导入器会把数组再序列化成字符串）：

```json
"loginUi": "[{\"name\":\"账号\",\"type\":\"text\"},{\"name\":\"密码\",\"type\":\"password\"}]"
```

> 空 `loginUi` + `loginUrl` 是普通 URL → 走**网页登录**；`loginUi` 非空或 `loginUrl` 是
> `@js:`/`<js>` → 走**表单 + 脚本登录**。

### 3.3 `exploreUrl` — 发现入口（4 种写法）

**写法 A：多行 `名称::URL`**（最常见）

```json
"exploreUrl": "現代奇幻::https://t66y.com/thread0806.php?fid=20&type=1&page={{page}},\n古典武俠::https://t66y.com/thread0806.php?fid=20&type=2&page={{page}}"
```

**写法 B：`&&` 分隔**（与 A 等价）

```
冒险::/sort/1&&热血::/sort/2
```

**写法 C：`@js:` / `<js>` 返回同样文本**（动态拼分类）

```json
"exploreUrl": "<js>\nu1='::/circlemarket/getBook,{\"method\":\"POST\",\"body\":\"start={{(page-1)*25}}&size=25&channelId=';\nlist=[[\"❀超星推荐❀\",130],[\"名家名作\",1000000008]];\nresult='';\nfor(var i=0;i<list.length;i++){result+=list[i][0]+u1+list[i][1]+'\"}\\n'}\n</js>"
```

**写法 D：`@js:` / `<js>` 返回 JSON 数组**（复杂逻辑）

```json
"exploreUrl": "<js>JSON.stringify([{title:'全年龄•全部',url:'https://www.missevan.com/mdrama?page={{page}}',style:{layout_flexGrow:1}}])</js>"
```

统一规则：
- 每项固定 `名称::URL`，URL 里可用 `{{page}}` 或 `<1,2,3>`（多页列表）
- 分类结果按 `md5(bookSourceUrl + exploreUrl)` 缓存，改 exploreUrl 自动失效
- `exploreUrl` 为空 → 该源不出现在发现页（哪怕 `enabledExplore=true`）

### 3.4 `searchUrl` — 搜索地址 + URL 选项

**基本形态**：URL 里用 `{{key}}`（关键词）与 `{{page}}`（页码）。

```json
"searchUrl": "/search?kw={{java.encodeURI(key)}}&page={{page}}"
```

**带选项形态**：URL 末尾用 `,` 接一个 JSON 对象（分隔正则 `\s*,\s*(?=\{)`，**逗号后必须紧跟 `{`**）：

```json
"searchUrl": "http://yz4.chaoxing.com/circlemarket/getsearch,{\"method\":\"POST\",\"body\":\"channelId=52&sw={{key}}&start=0&size=25\"}"
```

`UrlOption` 全部 12 个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `method` | String | 只有 `POST`（大小写不敏感）切 POST，其余都是 GET |
| `body` | Any | 请求体 |
| `headers` | Map | 额外请求头，**Content-Type 也在这里设** |
| `charset` | String | 响应字符集（`gbk` 等） |
| `retry` | Int | 重试次数 |
| `webView` | Boolean/Object | 走 WebView 加载 |
| `webJs` | String | WebView 加载后执行的 JS |
| `webViewDelayTime` | Long | 加载后再等多少毫秒 |
| `js` | String | 参数展开后对**最终 URL** 执行 JS，返回值替换 URL |
| `origin` | String | Referer 语义的源地址 |
| `serverID` | Long | 服务器 id（网络朗读） |
| `type` | String | 自定义类型标记，透传给 JS |

**没有** `contentType` / `sourceRegex` / `weight` 选项（`sourceRegex` 是 `ruleContent` 的字段，别搞混）。

### 3.5 表单编码陷阱（写 POST 源必看）

原文 `AnalyzeUrl.kt:266`：**只有请求头里没有 `Content-Type` 时**，body 才会自动做 URL 编码。

| 写法 | 结果 |
| --- | --- |
| `body: "k={{key}}"`，无 Content-Type | ✅ 自动表单编码，中文正常 |
| `body: "k={{java.encodeURI(key)}}"` + 显式 Content-Type | ✅ 手动编码 + 显式声明，最可控 |
| `body: "k={{key}}"` + 显式 Content-Type | ❌ 不编码，中文原样发出，多数站点报错 |
| `body: "k={{java.encodeURI(key)}}"`，无 Content-Type | ❌ 双重编码，`%` 变 `%25` |

## 附录 4：实现书源字段时最容易踩的 5 个坑

1. **`bookUrlPattern` 会抢在列表解析之前**：搜索响应一旦命中该正则，整个响应被当**单本详情页**
   解析并直接返回。所以该正则必须排除 `searchUrl` 自身路径（`/s`、`/sort`、`/data` 等），
   否则表现为「搜索有结果但字段全空」。
2. **`enabledCookieJar` 的默认值在 Kotlin 与数据库之间是矛盾的**（实体 `true` vs `DEFAULT 0`）。
   **已定的口径（2026-11-19，store-core）：两边都保留原样** —— 实体默认 `true`（导入 JSON 缺字段时走它），
   DDL 仍 `DEFAULT 0`（直接 SQL 不带该列时走它），`BookSourceDao` 的所有写入都**显式带上该列**，
   所以日常路径没有行为差异。**不要为了「统一」去改 DDL**：改了就和 Android 原版库对不上，
   备份文件互换时会读出不同的 Cookie 行为。
3. **规则块在 JSON 里是对象，在库里是 TEXT**。导入时是 `ruleSearch: {...}`，落库时要
   `jsonEncode`；导出时要 `jsonDecode` 回对象。中间任何一步多套了一层字符串，用户看到的就是
   「导入成功但规则全空」（`SearchRule.jsonDeserializer` 就是为兼容这种双层字符串写的）。
4. **`bookSourceGroup` 是逗号分隔的多值字段**，分隔符有全角：`[,;，；]`。用 `split(',')`
   会把 `"玄幻，都市"` 当成一个组名，分组列表里出现一个永远点不开的幽灵组。
5. **`respondTime` 单位是毫秒，默认 `180000` 是「未测过」的哨兵值**（3 分钟，真实响应只有几十到几百 ms）。
   直接展示会写出一行「respondTime: 180000 ms」。要区分「没测过」和「真的很慢」，只能靠这个哨兵值判断。
