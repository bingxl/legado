# 域实现顺序建议（并行切分）

> 依据：`docs/方法契约表.md`（156 方法 / 59 个被 UI 引用）、`docs/书源字段表.md`、
> `docs/flutter-全量迁移规划.md` 的 M1–M5 里程碑，以及 `legado-flutter/docs/并行开发契约.md`
> 的目录所有权。
>
> 结论先行：**先做「不碰网络、不碰规则引擎」的三个域（Settings / Tts / Shelf），
> 再做 Reader，最后才做 Source 与 Rss**。Source 一条链会把 rules / js / net 三个包同时拉进来，
> 一旦它先开工，另外三个 agent 的接口会被迫中途改。

---

## 一、依赖图

```
              ┌──────────── store（M1，已就绪：schema + 21 个 DAO）
              │
  ┌───────────┴────────────┐
  │                        │
Settings(0)  Tts(0)     Shelf(1) ──► Reader(2) ──► Cache(3)
  │            │            │            │            │
  │            │            └──► Bookmark(1) ◄──┐     │
  │            │            └──► Record(1)   ◄──┴─────┘
  │            │
  │        rules(M2 规则引擎) ──► Source(4) ──► Rss(3)
  │              │                  │            ▲
  │              │                  └──► SourceLogin / SourceDebug(后置)
  │              │
  │        js(M2 JS 解释器) ──► Source / Ai / Dict(规则脚本)
  │              │
  └──────── net(M2 网络层) ──► Source / Rss / WebDAV / Audio / Ai / Dict
```

括号内是**拓扑层级**（同一层可并行，数字越大越靠后）。

| 层级 | 域 | 前置依赖 | 说明 |
| --- | --- | --- | --- |
| L0 | `System` | — | 已实现，含 `System.Database`（store 提供） |
| L0 | `Settings` | store（`app_settings(key TEXT PK, value TEXT)`，**已由 store-core 建好**） | 纯键值 + Schema 声明，零外部依赖。值一律字符串；Kotlin 原版用 SharedPreferences，Dart 侧统一走 sqlite 才有 CLI 一致性 |
| L0 | `Tts` | 无 | 纯函数分段，连数据库都不用 |
| L1 | `Shelf` | store（book / book_group / chapter） | 只用 DAO，不发请求 |
| L1 | `Bookmark` / `Record` | store（bookmark / read_record）+ 进度读取器 | 与 Shelf 同层，注意 `chapterIndex<0` 需要读进度 |
| L2 | `Reader` | Shelf 的 Book + chapter DAO + 格式解析 | 本地书格式（txt 先行）是关键路径 |
| L2 | `Library` | bookparser（txt/epub）+ Shelf 落库 | 给 Shelf/Reader 造数据的最短路径 |
| L3 | `Cache` | Reader（章节）+ net | 整本缓存会调 Reader 的取章节能力 |
| L3 | `Rss` | store（rss_*）+ net + 少量规则 | **不依赖 Source**，可提前并行 |
| L4 | `Source` | store + **rules + net + js** | 全项目最重的域，38 个方法 |
| L4 | `ReplaceRule` | store（replace_rule）+ 正则 | 规则简单，但 Reader 正文净化要它 |
| L5 | `SourceLogin` / `SourceDebug` | Source + js + net | 依赖 Source 的抓取链路 |
| L5 | `Audio` / `Dict` / `Ai` / `WebDAV` | net / 平台播放器 / 向量 | 增强域，M5 |

## 二、6 个 agent 的并行切分（按目录，不按域数量平均）

`并行开发契约.md` 只划分了 store / rules / js / net 四个目录。进入 M5 服务层后建议这样切，
**每人独占一个 `lib/src/service/<域>/` 目录**，互不重叠：

| Agent | 独占目录 | 负责的方法 | 首阶段交付 |
| --- | --- | --- | --- |
| **store-core** | `lib/src/store/`、`lib/src/domain/` | 不注册方法，只供 DAO/实体 | 已有；只需补 `Library` 需要的 bookparser 落库入口 |
| **rules-engine** | `lib/src/rules/`、`lib/src/util/` | 不注册方法 | CSS/XPath/JSONPath + `@js:` 前缀分派 |
| **js-runtime** | `lib/src/js/` | 不注册方法 | JS 子集 + `JsEngine` 接口 |
| **net-layer** | `lib/src/net/` | 不注册方法 | HTTP + Cookie + 编码探测 |
| **service-book** | `lib/src/service/shelf/`、`reader/`、`library/`、`cache/` | Shelf 11 + Reader 5 + Library 2 + Cache 10 = **28** | Shelf + Reader 的 txt 链路 |
| **service-source** | `lib/src/service/source/`、`rss/`、`settings/`、`tts/`、`bookmark/` | Source 38 + Rss 10 + Settings 5 + Tts 1 + Bookmark 5 + Record 4 = **63** | Settings + Tts + Rss（Source 等 rules/net） |

> 6 个 agent 中 4 个（store/rules/js/net）是**基础包**，2 个是**服务层**。
> 服务层只有两个并行口，是因为 `Source` 与 `Shelf` 的公共文件冲突最多（都要动 `modules.dart`）。

## 三、每个域的最小可用切片（能跑通一条端到端链路）

| 域 | 最小切片 | 端到端验收（CLI） |
| --- | --- | --- |
| `Settings` | `Schema` + `Values` + `Update` | `legado call Settings.Update '["{\"reader.fontSize\":\"24\"}"]'` → `Values` 反映新值 |
| `Tts` | `Segment` | `legado call Tts.Segment '["很长的一段中文…",120]'` → 分片下标连续、不丢字 |
| `Shelf` | `ListGroups` + `ListBooks` + `GetBook` + `GetProgress` + `SaveProgress` | 手工插一行 book → `ListBooks` 有输出 → `SaveProgress` → `GetProgress` 读回同一进度 |
| `Library` | `ImportLocalFiles`（仅 txt） | 导入一个 txt → books/chapters 有行 → 交给 Shelf/Reader |
| `Reader` | `GetChapters` + `GetContent`（仅 txt） | `GetContent(bookId,0)` 返回非空 `html`，`prevIndex=-1`、`nextIndex=1` |
| `Bookmark` / `Record` | `Add` / `List` / `Clear` / `Stats` | 加一条书签 → `List` 读到 → `Remove` 后为空；`Record.Clear(0)` 返回条数 |
| `Rss` | `Source.List/Save` + `Article.List/Refresh` | 存一个 RSS 源 → `Refresh` 拉回 ≥1 篇 → `Article.List` 可见 → `MarkRead` 生效 |
| `Source` | `List/Get/Save/Delete/SetEnabled` + `Search`（单源、纯 CSS） | 导入 1 个纯 CSS 源 → `Source.Search` 返回结果 → `PreviewBook` 入库 → `Reader.GetChapters` 有目录 |
| `Cache` | `Start`（`scope=chapters`）+ `Status` + `Delete` | 缓存 3 章 → `Status.cachedChapters=3` → `Delete` 后归零 |
| `ReplaceRule` | `List` + `Save` + 应用到正文 | 存一条 `</?br>` 替换 → `Reader.GetContent` 的 `html` 里已生效 |

**判断标准**：切片跑通后 `legado methods -d <域>` 里的方法签名与本表一致，
且 UI 对应页面（`shelf_page` / `reader_page` / `rss_home_page` …）不再抛 `NOT_FOUND`。

## 四、公共文件 = 冲突源（必须提前约定）

| 公共文件 | 谁会改 | 冲突风险 | 约定 |
| --- | --- | --- | --- |
| `packages/legado_core/lib/src/modules/modules.dart` | 每个新域（加一行） | **最高**：6 个 agent 同改一个 list | 由**主控独占**；各域先在自己的 README 写「需要在 buildModules 加 `XxxModule()`」，主控批量合 |
| `packages/legado_core/pubspec.yaml` | 需要新依赖的域 | 高（workspace 单 lockfile） | 只由主控加；`dart pub add` 一律禁止 |
| `packages/legado_core/lib/src/core.dart`、`lib/legado_core.dart` | 需要暴露新类型时 | 高（门面导出面） | 主控独占；域内类用相对导入，不进导出面 |
| `packages/legado_core/lib/src/store/store.dart` | 新增 DAO 时（`StoreDaos` 21 行 + 字段） | 中（store-core 独占，天然无冲突） | 只有 store-core 改；服务域通过 `StoreModule.instance.daos` 读 |
| `packages/legado_core/lib/src/store/schema.dart` | 新增表/迁移 | 中 | store-core 独占；服务域不许 `CREATE TABLE` |
| `packages/legado_core/lib/src/kernel/**` | 任何人 | 高（错误码、Registry 语义） | **禁改**；缺能力走 `MethodDef.params` 表达 |
| `app/lib/core/bridge/api.dart` | 需要新方法常量的 UI 域 | 中 | 抬头已写「不要在本文件追加」，各 feature 自带 `_Api` 类 |
| `scripts/check-methods.ps1` | 校验口径变化 | 低 | 主控独占 |

### 服务层内部还会共享的两处

1. **进度读取器**：`Bookmark.Add` / `Record.Append` 的 `chapterIndex<0` 要读当前进度，
   `Reader` 也要写进度。建议由 `service/shelf` 提供 `ProgressReader` 接口，
   `bookmark` / `record` 通过构造注入拿 —— **不要各自查一次 `reading_progress` 表**，
   否则三处对「当前位置」的定义会漂。
2. **正文净化（ReplaceRule）**：`Reader.GetContent` 要用，`Cache` 缓存时也要用。
   归属 `service/replace/`（或被 `rules/` 接管），由 `Reader` 注入调用；
   **不要**在 Reader 里再实现一份。

## 五、建议排期（对应里程碑）

| 阶段 | 并行做的事 | 里程碑 |
| --- | --- | --- |
| 第 1 步 | Settings / Tts / Shelf（+ 契约表落地为 `params`） | M3 前半 |
| 第 2 步 | Library（txt）+ Reader（txt）+ Bookmark / Record | M3 收口：`导入 txt → 列表 → 读章 → 写进度` |
| 第 3 步 | rules + js + net 三包并行（无方法注册，纯能力） | M2 |
| 第 4 步 | Source（先 `List/Save/Search`）+ Rss（独立于 Source） | M2/M3 交叉 |
| 第 5 步 | Cache / ReplaceRule / 发现与搜索全链路 | M4 前后 |
| 第 6 步 | SourceLogin / SourceDebug / Audio / Dict / Ai / WebDAV | M5 |

**为什么不先做 Source**：`Source.Search` 一条链路要同时消费 `rules`（CSS/JSONPath 分派）、
`net`（Cookie/编码/重试）、`js`（`@js:` 规则）。这三个包在 M2 里自己都还没定稿，
Source 先开工的结果是「天天改别人正在写的接口」，且会把 `Shelf`/`Reader` 需要的
`BookBrief`/`ChapterItem` 形状带偏（书源侧想要的字段比阅读侧多）。

## 六、三条容易违反的红线

1. **不要在服务层直接 new DAO**：统一 `StoreModule.instance.daos`，否则 `close()` 后拿到旧连接，
   测试里表现为「第二个用例读到上一个用例的数据」。
2. **不要在 `lib/src/service/` 下新建顶层目录之外的东西**：`并行开发契约.md` §三.2 明确禁止
   在 M1–M2 阶段建 `lib/src/service/`，进入 M3 后才允许；开工前先确认主控已放开。
3. **不要为了让自己的测试通过而改 `MethodDef.params` 的字符串**：那是契约，
   CLI 的 `methods` 与 `check-methods.ps1` 都按它比对。参数顺序要改，先改
   `docs/方法契约表.md`，再改实现。
