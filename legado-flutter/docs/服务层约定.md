# 服务层约定（M3–M5）

> 第一批（数据/规则/JS/网络/格式）是**能力**，第二批是**业务**。
> 业务层最容易出现的问题不是写不出来，而是六个人各写一套 DTO、各定义一套错误码、
> 各自在 `modules.dart` 里抢同一行装配代码。这份约定就是为了把这三件事提前钉死。

## 一、目录与所有权

```
packages/legado_core/lib/src/service/
├── shelf/      书架、书籍、分组、章节列表、阅读进度
├── source/     书源 CRUD、导入导出、搜索、发现、调试、登录
├── reader/     正文加载、缓存、书签、替换净化落地
├── setting/    设置 Schema、阅读配置、主题
├── rss/        订阅源、文章、阅读记录、收藏
└── aux/        TTS、词典、AI、WebDAV/备份
```

每个域一个目录，目录内固定这几个文件：

| 文件 | 作用 |
| --- | --- |
| `xxx_service.dart` | 业务逻辑，构造时注入依赖（db/dao/net/rules） |
| `xxx_module.dart` | `implements CoreModule`，负责 `migrate`（本域建表）与 `register`（挂方法） |
| `dto.dart` | 本域对 UI 的返回结构（统一 `toJson()`） |
| `README.md` | 方法清单 + 参数 + 返回，供 `legado methods` 对照 |

**`modules.dart` 由主控统一改**，各域不要动它。交付时在 README 里写清
`name`、`dependsOn`、要注册的方法列表，由主控一次性接进去。

## 二、方法命名

`<Domain>.<Verb>`，Domain 是首字母大写的域名单数形式，Verb 用动词原形：

```
Shelf.ListBooks      Shelf.AddBook      Shelf.RemoveBook
Source.GetAll        Source.Save        Source.Import
Reader.GetContent    Reader.SaveDur     Reader.GetChapterList
```

已有的 157 个方法名来自旧 Go 内核，**必须一字不差**（大小写敏感）。
新增方法先在 `docs/方法契约表.md` 里加一行，再写实现。

参数一律**位置参数**，顺序即声明顺序；可选参数放最后并允许 `null`。
不要用命名参数 —— 信封协议里没有名字，只有数组。

## 三、DTO

- 一律手写 `Map<String, Object?> toJson()`，**不用 json_serializable**（多一层生成物，
  改字段要重跑 build_runner，并行时必冲突）。
- 字段名用 **camelCase**，与 Kotlin 的 `@SerializedName` / UI 侧 JS 保持一致。
- 时间统一 Unix 毫秒（`int`），与 Kotlin 的 `System.currentTimeMillis()` 一致；
  注意 Go 版用的是秒 —— 迁移时**逐个核对**，混用会导致时间显示 1970 年或 5 万年后的年份。
- 可空字段显式写 `null`，不要省略 key（UI 侧 `book.coverUrl` 取值不会 undefined）。

## 四、错误

统一用 `lib/src/kernel/errors.dart` 的 `LegadoException` + `ErrorCode`：

```dart
throw LegadoException(ErrorCode.notFound, '书籍不存在: $bookUrl');
```

**不要**自己造错误码字符串：UI 和 CLI 都按 `code` 分支，多一个码就多一处要改。
确实需要新码时，在契约表里登记，由主控加进 `errors.dart`。

## 五、依赖注入

服务只通过构造函数拿依赖，**不要全局单例、不要 Static 状态**（`dart test` 并行跑会串）。

```dart
class ShelfService {
  ShelfService({required this.db, required this.bookDao, required this.chapterDao});
  final Database db;
  final BookDao bookDao;
  final BookChapterDao chapterDao;
}
```

`*_module.dart` 里负责创建 DAO 与服务，并在 `register` 时把方法闭包挂到 registry：

```dart
final shelf = ShelfService(db: db, bookDao: BookDao(db), ...);
registry.method(
  'Shelf.ListBooks',
  (args) => shelf.listBooks(args.isEmpty ? 0 : args[0] as int),
  params: const ['group int?'],
  doc: '书架列表；group 为空或 0 表示全部',
);
```

`params` 是 `List<String>`，每项形如 `'group int?'`（`名称 类型`），
`legado methods` 直接导出它。签名以 `lib/src/kernel/registry.dart` 为准。

## 六、事务

- 批量写（导入书源、批量插章、批量改进度）**必须**在一个事务里：
  `db.execute('BEGIN'); try { ... db.execute('COMMIT'); } catch (e) { db.execute('ROLLBACK'); rethrow; }`
- 单条写不要开事务（sqlite 每条语句自带隐式事务，重复开只会变慢）。
- 不要在事务里 await 网络请求 —— 会把锁持有到超时。

## 七、测试

- 用 `sqlite3.openInMemory()` + 真实迁移建库，不要 mock DAO。
- 网络相关用本机 `HttpServer` 回环，不打外网。
- 每个方法至少一条正常路径 + 一条边界（空数据/不存在/参数越界）。
- 目标：每个域 ≥ 15 例。

## 八、交付清单

每个域交付时必须给：

1. 代码 + 测试全绿 + `dart analyze` 零 issue
2. `README.md`：模块名、依赖、方法表（方法名/参数/返回/说明）
3. `docs/进度-<域>.md`：做了什么、没做什么、留给谁、踩的坑
4. 明确告知主控：**需要往 `modules.dart` 加哪一行**
